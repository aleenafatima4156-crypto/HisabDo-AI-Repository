# HisabDo – Day 12 AI/ML Capstone

## Smart Expense Categorization

### Track
AI / ML

### Primary AI Feature
Smart Expense Categorization

### Objective

The objective of Day 12 is to make the Smart Expense Categorization
feature more application-ready by implementing structured input
handling, AI request processing, response validation, error handling,
and a basic API/service layer.

The project also defines how the AI service can communicate with the
HisabDo Website, Web Application, and Mobile Application.

---

# 1. Project Overview

Smart Expense Categorization automatically predicts an appropriate
category for a user's expense description.

Example:

Input:

"I bought groceries for dinner"

Output:

Food & Groceries

The system also returns a confidence score and processing time.

---

# 7. AI/ML Processing

## Step 1

The expense description is received by the Flask API.

## Step 2

Input validation checks the request.

## Step 3

TF-IDF converts the expense text into numerical features.

## Step 4

Logistic Regression predicts the expense category.

## Step 5

The model probability is used to calculate confidence.

## Step 6

Low-confidence predictions are handled as:

Uncategorized

## Step 7

The API validates the response.

## Step 8

A structured JSON response is returned to the application.

---

# 8. Confidence Handling

The current confidence threshold is:

0.40

If:

confidence >= 0.40

The predicted category is returned.

If:

confidence < 0.40

The category is returned as:

Uncategorized

This helps reduce unreliable automatic categorization.

# 11. Technical Considerations

## Data Privacy

Financial information should be protected using:

- HTTPS
- Authentication
- Authorization
- Secure storage
- Access controls
- Limited logging

## API Cost

The current POC uses a local machine learning model.

Therefore, it does not require an external AI API for each
expense prediction.

## Response Latency

The API records:

processing_time_seconds

This helps monitor prediction latency.

## Rate Limits

Production deployment should implement rate limiting to prevent
excessive API requests.

## Security

Production deployment should include:

- HTTPS
- Authentication
- Authorization
- Input validation
- Rate limiting
- Secure logging
- Financial data protection

## AI Errors

This project uses traditional machine learning rather than
generative AI.

Therefore, LLM-style hallucination is not the main concern.

However, the model can still make incorrect predictions.

Confidence scores, thresholds, and user confirmation can help
reduce this risk.

Detailed technical considerations are available in:

day12_technical_considerations.md
