# Day 12 – Realistic Use Cases

## AI Feature
Smart Expense Categorization

The Smart Expense Categorization service can automatically
classify user expenses into meaningful financial categories.

---

# Use Case 1 – Grocery Shopping

## Scenario

A user purchases groceries and enters the transaction
in the HisabDo application.

## Application Input

{
    "user_id": "U001",
    "expense": "I bought groceries and vegetables",
    "amount": 1800,
    "currency": "PKR",
    "date": "2026-08-12"
}

## AI Processing

1. The application sends the expense to the backend.
2. The backend sends the request to the `/categorize` API.
3. The API validates the input.
4. TF-IDF converts the description into numerical features.
5. Logistic Regression predicts the category.
6. The confidence score is calculated.
7. The response is validated.

## Expected Output

{
    "status": "success",
    "description": "I bought groceries and vegetables",
    "category": "Food & Groceries",
    "confidence": 0.XX
}

The actual confidence value is generated by the trained model.

## Benefit

The user does not need to manually select the expense
category, reducing data-entry effort.

# Use Case 3 – Fuel/Petrol Expense

## Scenario

A user records a petrol or fuel purchase for their vehicle.

    "user_id": "U003",
    "expense": "Filled petrol in my car",

1. Expense description is received by the API.

{

    "confidence": 0.XX
}

The actual confidence value is generated by the model.

## Benefit

Transportation expenses can be automatically organized
without requiring manual category selection.

---

# Low-Confidence Use Case

If an expense description is unclear, for example:

"Bought something yesterday"

the model may produce a low-confidence prediction.

If confidence is below the configured threshold of 0.40,
the API returns:

{
    "status": "success",
    "category": "Uncategorized",
    "confidence": 0.XX
}

This prevents the system from automatically assigning
an unreliable category.
