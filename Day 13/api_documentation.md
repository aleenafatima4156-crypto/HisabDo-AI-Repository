# HisabDo Smart Expense Categorization API

## 1. Overview

The Smart Expense Categorization API is an AI/ML service developed for the
HisabDo application.

It receives an expense description and related transaction information,
processes the description using a TF-IDF vectorizer and Logistic Regression
model, and returns a predicted expense category with a confidence score.

---

## 2. API Endpoint

Method:

POST

Endpoint:

/categorize

Local URL:

http://127.0.0.1:5000/categorize

Content-Type:

application/json

---

## 3. Input Format

The API accepts JSON data.

Example:

{
    "user_id": "U001",
    "expense": "I bought groceries for dinner",
    "amount": 2500,
    "currency": "PKR",
    "date": "2026-08-14"
}

### Input Fields

| Field | Type | Description |
|------|------|-------------|
| user_id | String | Unique application user identifier |
| expense | String | Expense description used by the ML model |
| amount | Number | Transaction amount |
| currency | String | Transaction currency |
| date | String | Transaction date |

---

## 4. AI Processing

The request follows this workflow:

Application
    ↓
Flask REST API
    ↓
Input Validation
    ↓
TF-IDF Vectorization
    ↓
Logistic Regression
    ↓
Category Prediction
    ↓
Confidence Calculation
    ↓
Response Validation
    ↓
JSON Response

---

## 5. Successful Response

Example:

{
    "status": "success",
    "user_id": "U001",
    "description": "I bought groceries for dinner",
    "amount": 2500,
    "currency": "PKR",
    "date": "2026-08-14",
    "category": "Food & Groceries",
    "confidence": 0.XX,
    "processing_time_seconds": 0.XX
}

The confidence and processing time values are generated by the running API.

---

## 6. Error Handling

The API validates incoming requests before sending data to the ML model.

### Missing Expense

Input:

{
    "user_id": "U002",
    "amount": 4500,
    "currency": "PKR"
}

Response:

{
    "status": "error",
    "message": "Expense description is required"
}

---

### Empty Expense

Input:

{
    "user_id": "U003",
    "expense": "",
    "amount": 2000,
    "currency": "PKR"
}

Response:

{
    "status": "error",
    "message": "Expense description cannot be empty"
}

---

### Invalid Expense Type

Input:

{
    "user_id": "U004",
    "expense": 12345,
    "amount": 3000,
    "currency": "PKR"
}

Response:

{
    "status": "error",
    "message": "Expense must be a string"
}

---

## 7. Low Confidence Handling

The model calculates a probability for the predicted category.

If the confidence is below the configured threshold, the API returns:

"Uncategorized"

This prevents the system from presenting a low-confidence prediction
as a reliable category.

---

## 8. Response Validation

Before returning the response, the API checks that the required fields
are available.

Required response fields include:

- status
- description
- category
- confidence

If the response structure is invalid, the API returns an error response.

## 11. Security Considerations

For production deployment:

- HTTPS should be used.
- API authentication should be implemented.
- User authorization should be enforced.
- Financial information should not be unnecessarily stored in logs.
- Input data should be validated and sanitized.
- Sensitive financial data should be protected.
- Access to stored transaction data should be restricted.

---

## 12. API Cost

The current POC uses a locally hosted ML model.

Therefore, there is no per-request external AI API cost.

Future external AI services may introduce:

- API usage charges

---

## 15. AI Error Handling

This feature does not generate free-form text, so traditional chatbot-style
hallucination is less relevant.

However, incorrect ML predictions can still occur.

To reduce this risk:

- Confidence scores are returned.
- Low-confidence predictions are marked as Uncategorized.
- User confirmation can be added in future versions.
- User-corrected categories can be collected for future model improvement.
